## 2. `~/.atomc/env.sh`

Generated by `scripts/bootstrap.sh`; safe to source repeatedly. Contents:

```bash
export PYRENODE_PATH="/Users/dtmirizzi/.local/opt/renode-1.17.0/Renode.app/Contents/MacOS/Renode"
export PYRENODE_RUNTIME="coreclr"
export QMK_HOME="${HOME}/qmk_firmware"
export PATH="/Users/dtmirizzi/.local/bin:/Users/dtmirizzi/.local/opt/renode-1.17.0/Renode.app/Contents/MacOS:$PATH"
export PATH="/opt/homebrew/opt/arm-gcc-bin@13/bin:$PATH"
export DOTNET_ROOT="/opt/homebrew/opt/dotnet@8/libexec"
export PATH="/opt/homebrew/opt/dotnet@8/bin:$PATH"
```

Key points:

- **`PYRENODE_PATH` only.** pyrenode3 0.0.1 reads `PYRENODE_PATH`; the older `PYRENODE_BIN` / `PYRENODE_PKG`
  variables are deprecated aliases and setting more than one of them raises
  `ImportError: Multiple Renode paths are set`. Point it at the `Renode` binary inside the app bundle;
  pyrenode3 detects the self-contained coreclr layout from the adjacent `System.dll`.
- **`PYRENODE_RUNTIME=coreclr`** is exported for documentation/tooling compatibility; pyrenode3 0.0.1
  hardcodes the coreclr load and does not read it.
- **`arm-gcc-bin@13` is prepended** so `arm-none-eabi-gcc` resolves to the full toolchain (13.2.1),
  not homebrew/core's bare 16.2.0.
- `dotnet@8` is keg-only, hence the explicit `DOTNET_ROOT` and PATH entries.

## 3. Workarounds (non-obvious)

### 3.1 pyenv `uv` shim breaks once `.python-version` = 3.14

On this machine `uv` was originally only available as a pyenv shim
(`~/.pyenv/shims/uv`, backed by pyenv 3.12/3.13). Writing `.python-version` = `3.14` makes pyenv
activate 3.14.0, where that shim has no `uv`, so every `uv` call in the repo fails with
`pyenv: uv: command not found`. Fix: `scripts/bootstrap.sh` resolves a real uv binary and copies it to
`~/.local/bin/uv`. `~/.local/bin` precedes `~/.pyenv/shims` on `PATH`, so `uv` keeps working after the
pin is written. (No shell rc files are modified.)

### 3.2 `gcc-arm-embedded` cask needs sudo; homebrew/core formula lacks newlib

- The brief's `brew install --cask gcc-arm-embedded` runs a `.pkg` installer via `sudo`, which cannot
  prompt in a non-interactive session. **Never used.** The orchestrator confirmed using a formula
  instead.
- homebrew/core `arm-none-eabi-gcc` 16.2.0 installs a compiler but **omits `nosys.specs`/`nano.specs`**,
  so QMK's compiler probe fails with
  `cannot read spec file 'nosys.specs': No such file or directory`.
- Solution: `brew install osx-cross/arm/arm-gcc-bin@13` — a **formula** (bottled, no sudo) that ships the
  complete GNU Arm 13.2 toolchain. It is keg-only, so it does not clash with the core formula; the
  bootstrap prepends `/opt/homebrew/opt/arm-gcc-bin@13/bin` to `PATH` in `env.sh` for QMK and the doctor.

### 3.3 QMK `doctor` also needs AVR/aux utilities

`qmk doctor` fails on this machine unless `avr-gcc`, `avrdude`, `dfu-programmer`, `dfu-util`, and
`dos2unix` are present. These are not needed for the STM32F411 example, but the bootstrap installs them
(all formulae, no sudo) so `qmk doctor` is fully green:

```bash
brew tap osx-cross/avr && brew trust osx-cross/avr
brew install osx-cross/avr/avr-gcc avrdude dfu-programmer dfu-util dos2unix
```

### 3.4 pnpm has no global bin dir

`pnpm add -g …` fails with `ERR_PNPM_NO_GLOBAL_BIN_DIR`, and `pnpm setup` edits shell rc files
(forbidden). The bootstrap installs global tools with `PNPM_HOME="$HOME/.local/bin"` so `turbo`/`biome`
land on the existing `PATH`.

### 3.5 Renode Gatekeeper quarantine

The portable `.dmg` is unsigned; the bootstrap clears the quarantine attribute
(`xattr -dr com.apple.quarantine …Renode.app`) after copying it out of the mounted image. `renode`
is symlinked onto `PATH` at `~/.local/bin/renode`.

### 3.6 Homebrew tap trust

Homebrew now requires explicit trust for third-party taps. The bootstrap runs
`brew trust osx-cross/arm` and `brew trust osx-cross/avr` before installing from them. Unrelated
untrusted taps (`gcenx/wine`, `grwnd-ai/grwnd`, `supabase/tap`) produce warnings during install but are
ignored.

### 3.7 No STM32G4 platform in Renode 1.17.0

The brief suggested `stm32g4` for the Renode smoke; Renode 1.17.0 ships **no** `stm32g4*.repl`. The
STM32F4 family is present and is the family the `atomc-keeb` example actually uses, so the smoke
proofs use `platforms/cpus/stm32f4.repl` / `stm32f412.repl` (closest to the F411).

### 3.8 atopile CLI maintenance mode

`ato` prints: *"atopile 0.15.8 is the last CLI release and is in maintenance mode only…"*. `0.15.9`
installs and builds fine. Missing-KiCad plugin warnings at startup are expected while KiCad is absent.

Result: exit 0, `volume_mm3 = 2398.743`, `step_bytes = 20282` (> 1 KB). `OCP` imports cleanly.

### 4.3 Renode headless: built-in STM32F4 demo + pyrenode3 load/start

Renode console, no XWT:

```bash
printf 'include @scripts/single-node/stm32f4_discovery.resc\nstart\nsleep 2\nquit\n' \
  | renode --disable-xwt --console
```

Result: exit 0. Contiki 3.x booted on the emulated STM32F4 Discovery and streamed to `uart4`:

```
uart4: Contiki 3.x started.
uart4:  * Ethernet process started
uart4:  * DHCP IP config started
uart4:  * UDP server started
… Machine paused. / Disposed.
```

No `HardFault` and no errors in the log (only expected unimplemented-register warnings).

pyrenode3 (from `./.venv`):

```python
from pyrenode3.wrappers import Emulation, Monitor
e = Emulation(); m = e.add_mach("f4")
m.load_repl("platforms/cpus/stm32f4.repl")   # @-relative to Renode root
mon = Monitor(); mon.execute("start"); time.sleep(1.0); mon.execute("pause")
```

Result: `Emulation()` constructed, `stm32f4.repl` loaded into a machine, and `start`/`pause` executed.
pyrenode3 + pythonnet + .NET 8 (coreclr) all work on macOS arm64.

### 4.4 arm-none-eabi-gcc: Cortex-M4 compile

```bash
arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -mno-thumb-interwork -O2 -g3 -x c -c main.c -o main.o
arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -mno-thumb-interwork \
  --specs=nosys.specs --specs=nano.specs -x c -o main.elf main.c
```

Result: exit 0 with gcc 13.2.1 (from `arm-gcc-bin@13`). `arm-none-eabi-size`: text 448, data 8, bss 36.
Only benign `_close`/`_read`/`_write`/`_lseek` "not implemented" warnings from `nosys`.

### 4.5 QMK compile (STM32F411) + boot in Renode

```bash
cd "$QMK_HOME"
qmk compile -kb handwired/onekey/blackpill_f411 -km default
# → .build/handwired_onekey_blackpill_f411_default.{elf,bin,hex}
```

Result: exit 0. Bin size 27428 bytes (59,732-byte file with bootloader offset), ELF 81,728 bytes.

Boot in Renode on the closest F411-class platform:

```bash
printf 'mach create\nmachine LoadPlatformDescription @platforms/cpus/stm32f412.repl\n%s\nstart\nsleep 2\nquit\n' \
  "sysbus LoadELF @$QMK_HOME/.build/handwired_onekey_blackpill_f411_default.elf" \
  | renode --disable-xwt --console
```

Result: exit 0, ran 2 s of emulated time with **no HardFault**. Observed warnings (informational, not
fatal): unimplemented DMA registers, reads/writes to non-existing peripherals
(`0xE0042008` DWT/ITM, `0xE0001000` DWT), and
`flash_controller: Attempted to write ... to a locked Control register`. CPU execution progressed
through flash (`0x0800_xxxx` addresses), i.e. the firmware is running its init/main loop; there is no
console output because the stock `onekey` keymap has no debug console enabled. This de-risks Phase 4:
QMK/ChibiOS images for the F411 load and run under Renode.

## 5. Known gaps / blockers for later phases

- **KiCad not installed** (optional). `ato build` layout steps that need KiCad will warn/SKIP until
  `bash scripts/bootstrap.sh --with-kicad` is run. No hard dependency for CLI/CI (D6).
- **No STM32F411-specific Renode platform**: Phase 4 (`plugin-renode`) should generate a `.repl`
  based on `stm32f412.repl` with the exact F411 memory map / GPIO ports used by the matrix, rather than
  relying on a stock board file.
- **QMK boot smoke is partial**: no HardFault and execution progresses, but no UART banner was
  asserted (the stock keymap has no console). Phase 4 will add a renode keymap with UART debug.
- **homebrew/core `arm-none-eabi-gcc` 16.2.0 is redundant** but harmless; it remains installed and is
  shadowed by `arm-gcc-bin@13` in `env.sh`.
- Renode/QMK/atopile versions are those observed on 2026-11-04; `Renovate`/plan §2 will track bumps.
